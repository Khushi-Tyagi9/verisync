verisync

Reconcile payments

Compare your payment gateway's records with your merchant's order records, and see which orders match, which can be safely corrected, and which need a person to look.

Recommendations only. This tool suggests corrections. It does not change any merchant system, and your files are not stored.

How it works
  1. Upload a gateway export and a merchant export (CSV or JSON), or load the sample.
  2. Verisync matches orders by order_id and compares the two statuses and amounts.
  3. Each order gets a verdict and a reason. Nothing is changed or stored.
What each verdict means
VerdictWhat it means
Safe to correct AUTO_CORRECTThe gateway captured the payment but the merchant record is behind (pending or failed), so marking the order paid is recommended.
Matches CONSISTENTBoth records agree: paid on both sides, or unpaid on both sides.
Risky FLAGGED_RISKYThe records conflict in a way that is never corrected automatically, such as a failed payment the merchant shows as paid.
Refund or dispute DISPUTEDA refund or dispute touches a payment that already settled, so a person has to handle it.
Data conflict CORRELATION_FAILEDTwo records for the same order disagree on amount or currency, so neither is trusted until the data is fixed.
Incomplete UNRESOLVEDOne side is missing, or the gateway has no final outcome yet, so there is nothing safe to compare.

Gateway captured but merchant behind is treated as safe to correct. Gateway failed but merchant shows paid is always flagged for a person.
